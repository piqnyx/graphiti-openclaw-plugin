# Формат JSON для `add_memory` (Graphiti OpenClaw plugin)

Согласовано: 2026-08-14. Пока не устареет — это канон.

## Зачем это нужно

Плагин буферизует сообщения из OpenClaw-сессии и периодически отправляет их в
Graphiti через `add_memory`. Мы передаём данные в **своём JSON-формате**, потому
что это даёт:

- **правильные имена акторов** в графе (а не безликие `User` / `Assistant`);
- больше контекста для построения связей между сущностями;
- реальные роли участников диалога.

## Структура JSON

```json
{
  "participants": {
    "user": "Вит",
    "assistant": "Краб"
  },
  "messages": [
    {
      "role": "user",
      "text": "Привет"
    },
    {
      "role": "assistant",
      "text": "Привет, Вит"
    }
  ]
}
```

### Поля

| Поле | Обязательно | Описание |
|---|---|---|
| `participants.user` | да | Каноническое имя пользователя = `Вит` |
| `participants.assistant` | да | Каноническое имя ассистента = `Краб` |
| `messages[].role` | да | `user` или `assistant` |
| `messages[].text` | да | Текст сообщения |

> **Канон зафиксирован (2026-08-14):** user = `Вит`, assistant = `Краб`. Всё прочее — алиасы, их прописывает пользователь в конфиге плагина сам.

## Lifecycle JSON (решено 2026-08-14, п.5)

- JSON создаётся **вместе с буфером** и **сразу пустым**: объект `participants` (акторы) присутствует, `messages` = `[]`.
- Это отдельная процедура «создание буфера»: создали буфер → создали пустой JSON с акторами.
- Добавление сообщений — **другая процедура**: берётся существующий JSON буфера, сообщение нормализуется (алиасы) и наталкивается в `messages`.

## Eligibility (минимум для эпизода) (решено 2026-08-14, п.1/Q3)

- В буфер никогда не попадает одиночный user без ответа бота: `extractCompletedTurn` захватывает пару **user+assistant** как единый блок, а без ответа ассистента возвращает `null` (в буфер ничего не идёт).
- Эпизод отправляется в Graphiti только если в JSON **>= 2 сообщений**.
- JSON с 0 или 1 сообщением НЕ отправляется (напр. бот затупил и не ответил — сообщение не станет мусорным эпизодом).
- Пустой JSON/буфер живет, ждёт второго сообщения.

## Чего НЕТ в формате (и почему)

### `dateTime` — нет
- Дефолтный промпт `extract_json` запрещает извлекать даты/время/таймстампы.
- Graphiti сам строит темпоральность через `reference_time` эпизода.
- Наши даты система всё равно проигнорирует, поэтому слать их бессмысленно.

### `custom_extraction_instructions` — нет
- Мы остаёмся на **дефолтном промпте** Graphiti, кастомный не используем.

## Параметры запроса `add_memory`

| Параметр | Значение |
|---|---|
| `source` | `json` |
| `reference_time` | `enqueuedAt` — момент ухода буфера в очередь, ISO-8601 (решено Q4) |
| `group_id` | `agentId` |
| `saga` | `sessionKey` |

### Про `custom_extraction_instructions` в конфиге
Принято решение кастомный промт **не делать вовсе** — поле не включаем в запрос.

## Про `reference_time` (решено 2026-08-14, Q4)

**`reference_time` — обязательное поле, передаём его мы (Graphiti сам не подставит).**

Зачем нужно:
- Дефолтный промт `extract_json` запрещает извлекать даты/время из текста — вся темпоральность эпизода висит на этом одном параметре.
- Без него эпизод уйдёт в Graphiti без привязки ко времени.

Что ставим:
- `reference_time` = `enqueuedAt` (момент, когда буфер ушёл в очередь, ISO-8601).
- Это время, когда все сообщения батча уже были получены — самая честная привязка «когда этот диалог произошёл». Все сообщения батча гарантированно были до этого момента.
- Не «время процессинга из головы очереди», а `enqueuedAt` — момент формирования батча.

## Имена акторов и алиасы

Канонические имена берутся **из конфига** при формировании JSON.
К каждому участнику — массив алиасов-регулярок (их пропишет пользователь в конфиге).

```json
{
  "participants": [
    {
      "role": "user",
      "name": "Вит",
      "aliases": ["..."]
    },
    {
      "role": "assistant",
      "name": "Краб",
      "aliases": ["..."]
    }
  ]
}
```

Зачем: Graphiti видит только канонические имена, в графе один узел `Вит`
и один узел `Краб`, а не десяток разных вариаций. Алиасы не засоряют граф.

Регулярки компилируются **один раз при старте плагина**, а не на каждое сообщение.

### Когда и где нормализуем алиасы (решено 2026-08-14, п.5)

Нормализация происходит **в момент добавления сообщения в JSON** (в тексте сообщения), а не только в participants.

- JSON изначально создаётся **пустым, только с объектом participants (акторы), без messages**.
- При добавлении каждого сообщения текст **нормализуется регулярками** из конфига.
- Назначение: чтобы к Graphiti не ушёл **никакой не-канонический актор прямо в тексте** сообщения.
- Пример: ассистент пишет «слушай, Виктор, а как дела?» — а канон `Вит`; слово «Виктор» заменится на каноничное `Вит`. Или юзер пишет «Крабушек, да всё окей» — канон `Краб`; слово «Крабушек» заменится на `Краб`.

## Примечание про разброс времени в батче

Таймер коммита 15 минут на неактивность, лимит батча 50 сообщений.
Теоретически можно растянуть батч на ~12 часов (по 1 сообщению каждые 14:59),
при этом `reference_time` будет = `enqueuedAt` (момент ухода буфера в очередь), что исказит временную линию.

Принято: **не чиним.** Это теоретический edge case, в среднем человек так не
пишет. Если на практике увидим искажение темпоральности — тогда отдельная задача
(возможно переход на `source=message` со своим таймстампом у каждого сообщения,
но ценой меньшего контекста связей).
